# 第11章 综合实战与测试验证

## 11.1 整机联调流程

整机联调是将机械、硬件、嵌入式软件、运动控制、感知、导航、任务系统等全部模块集成为一个可运行整体，并验证各模块协同工作的过程。对于轮腿式安保巡逻机器人，联调重点在于轮腿复合运动的稳定性和多系统数据流的正确性。

### 11.1.1 联调准备

在开始整机联调前，需完成以下准备工作：

| 项目 | 要求 | 检查方法 |
| :--- | :--- | :--- |
| 机械装配 | 所有螺栓紧固，关节转动灵活，线缆无干涉 | 手动转动关节，目视检查 |
| 硬件供电 | 各电压输出正常，电池电量充足 | 万用表测量各测试点 |
| 底层固件 | 已烧录最新版本，CAN通信正常 | USB-CAN工具收发测试 |
| 安全装置 | 急停开关有效，安全支架就绪 | 按下急停测试 |
| 测试场地 | 平整地面，周围无障碍，软垫防护 | 目视 |

### 11.1.2 分系统联调

整机联调前，应先进行分系统联调，确保每个子系统独立工作正常。

**机械与驱动联调**：

1. 空载状态下，逐个转动髋、膝关节，确认无卡滞、无异响。
2. 轮毂电机通电低速旋转，确认转向和编码器反馈正确。
3. 测试电磁制动器，断电抱闸、通电释放。

**底层控制联调**：

1. 发送速度指令，确认轮毂电机响应。
2. 发送关节角度指令，确认关节电机到达目标位置。
3. 检查IMU数据，确认姿态角解算正确。

**感知系统联调**：

1. 启动激光雷达和深度相机，确认数据发布。
2. 在Rviz中查看点云和图像，确认无异常。
3. 测试超声波传感器，确认距离数据合理。

**导航系统联调**：

1. 加载已有地图，运行AMCL定位。
2. 在Rviz中给定目标点，确认全局路径规划成功。
3. 启动局部规划器，确认避障行为正常。

**任务系统联调**：

1. 下发一个简单的定点巡逻任务，确认任务状态流转正常。
2. 模拟异常事件，确认报警和处理逻辑正确。

### 11.1.3 整机联调步骤

分系统联调通过后，进行整机联调。整机联调遵循“先空载后负载、先静后动、先慢后快”的原则。

**步骤1：空载上电自检**

机器人置于安全支架上，上电启动所有系统。观察各节点启动状态，确认无报错。检查`/robot_state`话题，数据应正常发布。

**步骤2：静态平衡测试**

撤去安全支架，机器人落地。发送站立指令，观察机器人是否能稳定站立。轻微推动，观察平衡恢复能力。此时轮子可以锁死或处于速度环。

**步骤3：低速轮式移动**

发送低速前进指令（0.2 m/s），观察机器人是否能直线行驶。然后测试差速转向（0.3 rad/s），观察转向是否平滑。逐步提高速度至1.0 m/s。

**步骤4：腿式动作测试**

切换至腿式模式，执行蹲起动作。观察关节轨迹和身体高度变化。然后执行原地踏步（轮流抬腿），确认步态稳定。

**步骤5：越障功能测试**

在平坦地面放置一个50 mm高的台阶，让机器人以0.3 m/s接近，触发腿式越障。观察越障动作是否连贯、稳定。

**步骤6：自主导航测试**

加载地图，发送目标点，让机器人自主导航。在路径中放置动态障碍物，观察避障行为。导航过程中注意定位精度和路径跟踪。

**步骤7：完整任务闭环**

下发巡逻任务，包含多个路径点和一次越障区域。观察机器人是否按计划完成巡逻并返回。

整机联调中常见问题及处理：

| 问题 | 可能原因 | 处理方法 |
| :--- | :--- | :--- |
| 机器人无法站立 | 平衡控制器参数不正确、IMU零偏未校准 | 重新标定IMU，调整LQR增益 |
| 轮式移动抖动 | 速度环增益过大、编码器噪声 | 降低速度环Kp，滤波编码器 |
| 转向过度/不足 | 差速解算错误、轮径不一致 | 校准轮径，修正轮距参数 |
| 越障时摔倒 | 步态轨迹不合理、重心超出支撑域 | 调整步态参数，降低抬腿高度 |
| 导航定位丢失 | 激光雷达被遮挡、AMCL粒子发散 | 清洁雷达，重新设置初始位姿 |

## 11.2 可视化监控界面设计

### 11.2.1 界面布局

监控界面采用三栏布局：

- **左侧**：视频显示和报警列表。
- **中间**：地图显示机器人位置和巡逻轨迹。
- **右侧**：状态面板（电量、模式、速度等）和遥控按钮。

### 11.2.2 状态面板实现

状态面板订阅`/robot_state`话题，解析并显示。机器人状态数据打包为`Float32MultiArray`，字段顺序为：俯仰角、髋关节角、轮速、故障码、电池电压、电流、模式等（定义于第5章）。

```javascript
const statusListener = new ROSLIB.Topic({
  ros: ros,
  name: '/robot_state',
  messageType: 'std_msgs/Float32MultiArray'
});

statusListener.subscribe((msg) => {
  const data = msg.data;
  document.getElementById('pitch').innerText = (data[0]).toFixed(3) + ' rad';
  document.getElementById('hip_angle').innerText = (data[1]).toFixed(2) + ' rad';
  document.getElementById('wheel_speed').innerText = (data[2]).toFixed(1) + ' rpm';
  const fault = data[3];
  document.getElementById('fault_code').innerText = fault;
  // 如果后续有电压电流，继续解析
  // ...
});
```

### 11.2.3 地图显示

地图使用ros2djs（或nav2djs）加载栅格地图，并标记机器人位置。也可使用静态地图图片配合CSS定位。简化方案：订阅/amcl_pose话题，将机器人坐标映射到地图图片上的像素点。

```javascript
// 订阅AMCL定位
const poseListener = new ROSLIB.Topic({
  ros: ros,
  name: '/amcl_pose',
  messageType: 'geometry_msgs/PoseWithCovarianceStamped'
});

poseListener.subscribe((msg) => {
  const x = msg.pose.pose.position.x;
  const y = msg.pose.pose.position.y;
  // 地图分辨率0.05m/pixel，原点在左下角
  const pixelX = x / 0.05;
  const pixelY = (mapHeight - y / 0.05);
  updateRobotMarker(pixelX, pixelY);
});
```

### 11.2.4 报警提示

订阅/anomaly_events话题，收到报警后弹出提示并显示现场图像（如果消息中包含图像或通过独立话题获取）。

```javascript
const anomalyListener = new ROSLIB.Topic({
  ros: ros,
  name: '/anomaly_events',
  messageType: 'std_msgs/String'
});

anomalyListener.subscribe((msg) => {
  const event = JSON.parse(msg.data);
  alert(`异常事件：${event.type}，等级：${event.severity}`);
  // 请求现场图像
  fetchSnapshot();
});
```

### 11.2.5 遥控按钮

在遥控模式下，通过按钮发送/cmd_vel指令。按钮按下时发送固定速度，松开时发送零速度。

```html
<button onmousedown="sendVelocity(0.5, 0)" onmouseup="sendVelocity(0, 0)">前进</button>
<button onmousedown="sendVelocity(-0.5, 0)" onmouseup="sendVelocity(0, 0)">后退</button>
<button onmousedown="sendVelocity(0, 1.0)" onmouseup="sendVelocity(0, 0)">左转</button>
<button onmousedown="sendVelocity(0, -1.0)" onmouseup="sendVelocity(0, 0)">右转</button>
```

## 11.3 故障诊断与维修

### 11.3.1 常见故障分类

根据故障来源，将常见故障分为机械、电气、软件三类：

| 类别 | 典型故障 | 表现 |
| :--- | :--- | :--- |
| 机械 | 关节轴承磨损、螺栓松动、轮胎磨损 | 关节晃动、异响、跑偏 |
| 电气 | 电机驱动损坏、电源故障、传感器失灵 | 电机不转、系统重启、数据异常 |
| 软件 | 控制参数错误、通信超时、内存溢出 | 运动异常、节点崩溃、系统卡顿 |

### 11.3.2 诊断流程

故障诊断遵循“先软后硬、先简后繁”的原则：

1. **现象记录**：记录故障发生时的运行状态、环境条件、操作步骤。
2. **日志分析**：查看ROS日志（`rosout.log`）、底层故障码、数据库记录。
3. **分系统隔离**：逐一关闭或断开非必要模块，缩小故障范围。
4. **硬件检测**：使用万用表、示波器、逻辑分析仪检测硬件信号。
5. **软件调试**：使用`rostopic echo`、`rqt`、GDB等工具定位软件问题。

### 11.3.3 维修与更换

对于诊断出的故障，进行维修或更换部件：

**机械维修**：

- 螺栓松动：按扭矩复紧。
- 轴承磨损：更换同型号轴承。
- 轮胎磨损：更换轮胎或整个轮毂电机轮。

**电气维修**：

- 驱动芯片损坏：更换MOS管或驱动芯片。
- 电源模块故障：更换DC-DC模块。
- 传感器损坏：更换传感器并重新标定。

**软件修复**：

- 参数错误：调整PID/LQR参数，重新标定。
- 代码缺陷：修复代码后重新编译部署。

维修后需进行功能验证，确保故障消除且未引入新问题。

## 11.4 现场部署与运维

### 11.4.1 部署前准备

现场部署前需完成以下工作：

| 项目 | 内容 |
| :--- | :--- |
| 现场勘察 | 了解巡逻区域地形、网络覆盖、光照条件 |
| 地图构建 | 使用机器人在现场建图，保存高精度地图 |
| 路径规划 | 根据巡逻需求设置路径点和禁入区域 |
| 网络配置 | 配置Wi-Fi/4G，确保远程监控可用 |
| 安全评估 | 识别可能造成机器人损坏或伤人的风险点 |

### 11.4.2 现场部署流程

1. **机器人运输**：将机器人运至现场，注意防震、防潮。
2. **上电自检**：开机运行自检程序，确认各系统正常。
3. **初始定位**：在已知起点启动AMCL，确认定位成功。
4. **试运行**：进行短距离自主导航测试，观察避障和越障。
5. **任务下发**：通过远程监控端下发巡逻任务。
6. **监控与调整**：在监控端观察运行状态，根据实际调整参数。

### 11.4.3 运维管理

日常运维包括：

- **每日检查**：检查轮胎气压、螺栓紧固、电池电量。
- **每周维护**：清洁传感器镜头，检查线缆连接。
- **每月保养**：关节润滑、电池容量检测、软件日志清理。
- **故障处理**：按11.4节流程快速诊断和维修。

建立运维记录表，记录每次维护和故障处理情况，便于追踪和改进。

## 11.5 实战：从样机到巡逻任务完整闭环

### 11.5.1 任务目标

在本实战中，读者将把前面所有章节的工作整合起来，完成从一台散件样机到执行实际巡逻任务的完整闭环。任务包括：装配、上电、调试、建图、部署、巡逻、评估。

### 11.5.2 实施步骤

**阶段一：样机准备**

1. 完成机械装配（第3章），确保所有部件安装到位。
2. 完成硬件接线（第4章），上电测试各电压。
3. 烧录底层固件（第5章），验证CAN通信和电机控制。
4. 启动上层软件，检查ROS节点和话题。

**阶段二：功能验证**

1. 验证轮式模式移动和转向（第7章）。
2. 验证腿式模式越障和蹲起（第7章）。
3. 验证环境感知和目标检测（第8章）。
4. 验证自主导航和避障（第9章）。

**阶段三：场景部署**

1. 在目标园区进行建图，保存地图。
2. 设置巡逻路径点和禁区。
3. 配置远程监控终端（第10章）。
4. 进行试运行，调整参数。

**阶段四：任务执行与评估**

1. 下发正式巡逻任务，运行至少2小时。
2. 记录巡逻轨迹、报警事件、电量消耗。
3. 统计路径点到达率、报警准确率、续航时间。
4. 撰写测试报告，总结问题和改进建议。
